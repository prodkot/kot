# Обновления со своего VPS

Официальная сборка уже использует GitHub. Свой VPS нужен, если хочешь раздавать обновления с собственного адреса. Приложению достаточно двух файлов: подписанного ZIP и небольшого `latest.json`.

## Подготовить файлы

Сначала получи готовый подписанный ZIP. Можно скачать его из [Releases](https://github.com/prodkot/kot/releases/latest) и разместить как есть. Для своей сборки используй [инструкцию по выпуску](GITHUB.md).

Пример для версии 0.4.2:

```sh
python3 Release/feed.py Kot-Client-0.4.2-beta-Windows-x64.zip --url https://updates.example.com/kot/Kot-Client-0.4.2-beta-Windows-x64.zip --output latest.json
```

Замени `updates.example.com` на свой домен. Скрипт прочитает версию из архива и сам подставит его размер. Получится JSON с тремя полями:

- `version`: версия приложения, например `0.4.2`.
- `url`: прямая HTTPS-ссылка на этот ZIP.
- `size`: точный размер ZIP в байтах.

Не редактируй файлы внутри подписанного архива. Если что-то поменял, пакет нужно заново собрать и подписать тем же ключом.

## Разместить на сервере

Нужен веб-сервер, который раздаёт обычные статические файлы по HTTPS. Если на VPS уже есть сайт, можно сделать отдельную папку `/kot/`.

1. Загрузи ZIP полностью.
2. Положи рядом `latest.json`. Лучше сначала загрузить его под временным именем, а затем переименовать, чтобы клиент не получил обрезанный файл.
3. Проверь, что JSON и архив открываются по прямым ссылкам без входа в аккаунт. У JSON отключи долгое кеширование, чтобы новые версии появлялись сразу.

Пример адресов:

```text
https://updates.example.com/kot/latest.json
https://updates.example.com/kot/Kot-Client-0.4.2-beta-Windows-x64.zip
```

Нужен действующий сертификат, которому доверяет Windows. Обычный HTTP, самоподписанный сертификат без доверия и ссылки с логином или паролем не подходят. Приватный ключ издателя на сервер раздачи загружать не нужно.

## Подключить приложение

Открой **Настройки → Обновления**, выбери **HTTPS на VPS** и вставь адрес `latest.json`. Сохрани источник и нажми «Проверить».

Клиент предлагает только более новую версию. Поэтому уже установленная 0.4.2 не предложит скачать такую же 0.4.2. Для проверки самого обновления нужен следующий выпуск, подписанный прежним ключом.

Чтобы обновления устанавливались сами, включи **Скачивать и устанавливать автоматически**. Приложение проверяет источник при старте и раз в сутки, пока работает. При ошибке следующая попытка будет примерно через 15 минут. Ручная проверка показывает отдельную кнопку установки.

## Выпустить следующую версию

Собери новый ZIP, создай для него JSON и сначала загрузи архив. Только после этого замени `latest.json`. Адрес JSON остаётся тем же; в нём меняются версия, ссылка и размер.

Хостинг сообщает, где взять пакет. Право на установку подтверждает его подпись: даже файл с твоего VPS не пройдёт проверку с чужим ключом, повреждённым содержимым или неверной версией.

При установке kot. отключает соединение, заменяет файлы в текущей папке и перезапускается. Подписки и HWID сохраняются. При ошибке замены или запуска интерфейса предусмотрен откат. Полный сценарий ещё требует проверки на Windows; после внезапного сбоя питания полного автоматического восстановления пока нет.

## Лимиты

На проверку источника даётся 20 секунд, на скачивание пакета 10 минут. JSON ограничен 1 МБ, архив и распакованное содержимое 600 МБ. Разрешено до пяти перенаправлений, без перехода с HTTPS на HTTP.

Токен GitHub для официальных обновлений не нужен. Приватные репозитории и хостинг, требующий авторизации, сейчас не поддерживаются.
