# Канал обновлений kot. 0.3.1

Клиент поддерживает GitHub Releases и HTTPS JSON на VPS. Источник задаётся в «Настройки -> Обновления». Проверка выполняется после запуска и раз в 24 часа, пока приложение работает. Выключатель отключает фоновую проверку; кнопка «Проверить» остаётся доступной. Установка начинается по кнопке пользователя. Подключение к VPN не прерывается ради фоновой проверки; при установке приложение закрывает своё ядро и запускает новую версию.

Никакой адрес по умолчанию не выдуман. GitHub-репозиторий или публичный VPS должны существовать и содержать релиз. В поставке не настроен живой хостинг.

## GitHub

1. Создайте публичный репозиторий либо используйте существующий.
2. Создайте опубликованный Release с тегом вида `v0.3.2`. GitHub API `releases/latest` не возвращает draft и prerelease, поэтому для этого канала релиз не должен быть отмечен prerelease. Имя ZIP может содержать `beta`: это имя файла, а не отметка GitHub.
3. Загрузите подписанный архив без переименования: `Kot-Client-0.3.2-beta-Windows-x64.zip`. Нужны файлы `release.json` и `release.sig` внутри ZIP, в его корне.
4. В приложении выберите GitHub Releases и введите `owner/repository`, затем «Сохранить источник» или «Проверить». Токен GitHub не нужен; приватные репозитории не поддерживаются.

Для текущей версии имя `Kot-Client-0.3.1-beta-Windows-x64.zip`, тег `v0.3.1`. Клиент 0.3.1 не предложит переустановить эту же версию.

Запросы выполняются к официальному API GitHub. Автоматически выбирается только asset с точным именем для соответствующей версии Windows x64. `releases/latest` означает последний опубликованный обычный релиз по правилам GitHub, а не поиск максимального числа среди всех тегов.

Документация API: https://docs.github.com/en/rest/releases/releases#get-the-latest-release

## VPS

На VPS разместите готовый подписанный ZIP и JSON. Пример создания JSON:

```sh
python3 Release/feed.py Kot-Client-0.3.2-beta-Windows-x64.zip --url https://updates.example.com/kot/Kot-Client-0.3.2-beta-Windows-x64.zip --output latest.json
```

Публикуйте `latest.json` только после загрузки полного ZIP. Пример формата:

```json
{
  "version": "0.3.2",
  "url": "https://updates.example.com/kot/Kot-Client-0.3.2-beta-Windows-x64.zip",
  "size": 80000000
}
```

Размер должен соответствовать фактическому архиву. В клиенте выберите «HTTPS на VPS» и укажите HTTPS URL JSON. Сертификат должен проверяться Windows, без отключения TLS. Домен `updates.example.com` здесь является примером, а не существующим каналом приложения.

## Подпись и сборка

Клиент не доверяет EXE только потому, что он скачан с GitHub/VPS. После скачивания проверяются подпись RSA-3072, SHA-256 каждого файла, безопасные пути и более новая версия. Версия подписанного архива должна совпадать с версией источника. Пустой, повреждённый, неподписанный, подписанный чужим ключом и более старый архив не устанавливаются. Метаданные GitHub/JSON нужны для поиска, а не заменяют подпись.

`build.ps1` создаёт publish-папку. Подписание:

```sh
python3 Release/sign.py PATH_TO_PUBLISH 0.3.2 --key PATH_TO_MATCHING_PRIVATE_KEY
```

Перед сборкой меняйте версию проекта и `ClientIdentity.Version` в Core/ClientIdentity.cs, остальные строки версии интерфейса/диагностики и User-Agent. `AppVersion` и имя устройства используют `ClientIdentity.Version`. Архивируйте содержимое publish-папки без дополнительной внешней папки. Сначала подписывайте окончательные файлы, затем создавайте ZIP. Любая правка после подписания требует новой подписи.

Публичный ключ закреплён в Core/ReleaseKey.cs. Приватного ключа этой линии сборок в исходниках нет. Готовые архивы этой линии уже подписаны и могут публиковаться как есть. Для независимого форка создайте свою RSA-пару, замените публичный ключ, пересоберите первый клиент и подписывайте дальнейшие версии соответствующим приватным ключом. Подписанный другим ключом форк не устанавливается поверх этой линии через обновлятор.

```sh
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out private.pem
openssl pkey -in private.pem -pubout -out public.pem
```

Приватный ключ храните вне publish, репозитория и архивов. Для CI ключ можно предоставить через секрет хостинга, не через исходники. Хостинг, домен и секрет CI в этой поставке не созданы.

## Установка

Архив скачивается во временный файл профиля, проверяется и распаковывается в новую папку `Kot-ВЕРСИЯ` под выбранным пользователем каталогом. Предыдущая версия остаётся для возврата. Новый EXE ждёт завершения старого и обновляет задачу автозапуска, если она включена. После завершения/отмены скачанный временный ZIP удаляется. Перенос профиля не требуется.

Сеть: только HTTPS, максимум 5 перенаправлений, запрет перехода на HTTP и URL с логином/паролем. JSON ограничен 1 МБ; архив и его распакованные файлы ограничены 600 МБ. Общий таймаут проверки 20 секунд, скачивания 10 минут; отмена работает также при зависшем теле ответа. Нативный путь установки требует проверки на Windows.
