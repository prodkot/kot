# Разработка 0.6.2

Ветка `dev/0.6.2` создана от актуальной `main`. Новые функции и исправления для следующей версии накапливаются здесь. Версия 0.6.1 остаётся сборкой для длительной проверки пользователем.

0.6.2 пока не опубликована. Начальный коммит меняет номера версии и организацию разработки; поведение приложения соответствует 0.6.1. Исправление накопления исторических данных AppLog остаётся первой задачей следующего цикла.

## Проверки и тестовый установщик

- Workflow **Windows checks** запускается при push в `dev/**` и проверяет логику, интерфейс, реальные Windows-процессы, окно и трей.
- Workflow **Windows development build** запускается при push в `dev/**` или вручную на такой ветке. Он собирает подписанный Setup, проверяет настоящее подключение TUN, kill switch, установку и удаление.
- После успешной сборки установщик доступен в артефакте `windows-development` соответствующего запуска Actions. Срок хранения артефакта 30 дней. Для скачивания GitHub может потребовать вход в аккаунт.
- Тестовый установщик заменяет установленный клиент. Для длительного испытания 0.6.1 следует продолжать пользоваться именно её сборкой.

У workflow разработки только разрешение `contents: read`. В нём нет создания тегов или публикации GitHub Releases. Его имя отличается от workflow выпуска, поэтому завершение тестовой сборки не запускает публикацию сайта, подписанную на **Windows release**.

## Слияние и выпуск

Эту ветку можно слить в `main` обычным pull request. Перед слиянием нужно закончить изменения, обновить [заметки версии](NOTES.md), проверить результаты CI и разрешить конфликты, если `main` успела измениться.

Слияние само по себе не создаёт релиз приложения. Публикация 0.6.2 отложена до отдельного решения пользователя после длительной проверки 0.6.1. До этого не нужно создавать или отправлять тег `v0.6.2` и запускать **Windows release** с включённой публикацией.

Обычный порядок выпуска описан в [GITHUB.md](GITHUB.md).
