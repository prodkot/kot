# Выпуск версии

1. Обнови номер в `Core/ClientIdentity.cs`, `Windows/Kot.Windows.csproj`, `Windows/app.manifest`, интерфейсе и `Installer/Kot.nsi`.
2. Запиши изменения в `Release/NOTES.md` и `CHANGELOG.md`.
3. Запусти `python Tests/repository.py`, проверки из [docs/BUILD.md](../docs/BUILD.md) и CI pull request.
4. Сначала запусти workflow **Windows release** вручную на ветке PR с выключенной галочкой публикации: он проверит подписанный Setup без публикации. После успешных проверок слей PR.
5. Открой **Actions → Windows release → Run workflow**, выбери ветку `main`, включи галочку **«Опубликовать новую версию из main в Releases»** и запусти workflow. После сборки и проверок он создаст тег `vНОМЕР` на том же коммите и опубликует установщик.

Если галочка выключена, ручной запуск только собирает и проверяет установщик. Публикация вручную разрешена только из `main`; существующий тег не перезаписывается. Альтернативный способ выпуска сохраняется: создать тег `vНОМЕР` на проверенном коммите `main` и отправить его на GitHub. Заранее создавать страницу релиза не нужно.

Перед сборкой workflow проверяет совпадение тега с версией клиента и принадлежность публикуемого коммита истории `origin/main`. Тег на неслитой ветке отклоняется. Для проверки истории checkout получает все коммиты; предварительная сборка PR без публикации остаётся доступной.

В сборках `v0.8.0-xray.N` внутренняя версия клиента тоже `0.8.0`. Пользователям этих сборок нужно установить финальный `v0.8.0` новым Setup вручную: встроенный обновлятор предлагает только более высокий номер версии.

Workflow соберёт Setup, подпишет вложенный пакет ключом `KOT_RELEASE_SIGNING_KEY` из GitHub Secrets и опубликует один установщик. Текст страницы релиза берётся из `Release/NOTES.md`.

Приватный ключ хранится вне репозитория. Его публичная часть уже закреплена в клиенте. Не заменяй ключ при обычном обновлении: предыдущие клиенты не примут новую подпись.

Для локального выпуска на Windows нужны NSIS 3, Python 3, .NET 10 SDK, PowerShell 7 и Visual Studio 2022 или новее с компонентом **Desktop development with C++** для нативной программы распаковки и небольшой DLL оформления установщика:

```powershell
pwsh ./Release/release.ps1 -Key 'C:\private\kot-release.pem'
```

В `artifacts` останется только Setup. ZIP используется внутри сборки и встраивается в Setup один раз, отдельно не публикуется. NSIS содержит собственные страницы и небольшую нативную DLL оформления, шрифт Manrope, программу распаковки NativeAOT и команды ярлыков и удаления; второго комплекта файлов приложения в нём нет. Перед публикацией Setup повторно проверяется клиентским валидатором и нативной программой распаковки.

В CI сборка также проверяет обновление этим Setup через настоящий updater версии 0.6.1 с запуском нового WebView2. Локальная сборка не запускает эту проверку над обычным аккаунтом разработчика. Её можно выполнить отдельно в чистом тестовом аккаунте Windows через `Release/setup-checks.ps1 -Setup <exe> -Extractor <native-exe> -Publish <publish-folder> -Version <version> -LegacyUpdate`.
