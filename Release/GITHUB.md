# Релизы и установщик

Официальный репозиторий: [prodkot/kot](https://github.com/prodkot/kot). GitHub Actions уже настроен: по тегу он собирает приложение, подписанный ZIP и установщик, затем публикует их в Releases.

## Выпустить следующую версию

1. Поменяй версию в `Core/ClientIdentity.cs`, `Windows/Kot.Windows.csproj` и `Windows/app.manifest`. В манифесте у версии есть четвёртая часть, например `0.4.2.0`.
2. Обнови запасную версию в `Windows/ui/index.html`, примеры в тестах и описание изменений в `CHANGELOG.md`. Рабочий интерфейс получает номер версии из приложения.
3. Напиши короткое описание выпуска в `Release/NOTES.md`: что изменилось и что нужно знать перед установкой.
4. Закоммить изменения и отправь тег с тем же номером.

Например, для 0.4.2:

```powershell
git add .
git commit -m "Release 0.4.2"
git tag v0.4.2
git push origin main
git push origin v0.4.2
```

После успешной сборки в Releases появятся:

- `Kot-Setup-0.4.2-Windows-x64.exe`: обычный установщик.
- `Kot-Client-0.4.2-beta-Windows-x64.zip`: portable-версия и пакет автообновления.
- `SHA256SUMS.txt`: контрольные суммы.

Релиз должен быть опубликован, без галочек **Draft** и **Pre-release**. Автообновление использует канал `latest` и не выбирает такие выпуски. Слово `beta` в имени ZIP не требует галочки Pre-release. ZIP не переименовывай: приложение ищет точное имя.

Проверить сборку без публикации можно через **Actions → Windows release → Run workflow**. Результат будет в артефактах этого запуска.

## Сделать установщик на своём компьютере

Нужны Windows x64, .NET 10 SDK, PowerShell 7, Python 3 и NSIS 3.

```powershell
pwsh ./Release/release.ps1 -Key "C:/Kot-Keys/release-private.pem" -Repository "prodkot/kot"
```

Скрипт соберёт программу, подпишет ZIP, проверит его тем же кодом, что использует приложение, и сделает установщик NSIS. Результат будет в `artifacts/`. Если NSIS установлен не в стандартную папку, передай путь к `makensis.exe` через `-Nsis`.

Установщик кладёт программу в Program Files, создаёт ярлыки и добавляет удаление через Windows. Перед ручной установкой закрой старую версию и отключи VPN. Профиль хранится отдельно в LocalAppData: установка поверх и удаление программы его не стирают.

## Ключ издателя

У официального репозитория уже есть секрет `KOT_RELEASE_SIGNING_KEY`. Он соответствует ключу, которому доверяет ранее присланная версия 0.4.0. Создавать новый ключ для очередного выпуска не нужно.

Публичный ключ находится в `Core/ReleaseKey.cs`. Приватный нужен только для подписи. Его нельзя коммитить, прикладывать к релизу или вставлять в открытый issue.

## Если это твой форк

Создай публичный репозиторий и загрузи в его корень содержимое исходников. Папки `Core`, `Windows`, `Release`, `.github` и `build.ps1` должны лежать прямо в корне.

Затем сделай свой ключ:

```powershell
New-Item -ItemType Directory -Force C:/Kot-Keys
pwsh ./Release/new-key.ps1 -PrivateKeyPath "C:/Kot-Keys/release-private.pem"
```

Скрипт обновит публичный ключ в `Core/ReleaseKey.cs`. Его закоммить, а приватный PEM оставь вне репозитория и сохрани резервную копию.

В **Settings → Secrets and variables → Actions** создай секрет `KOT_RELEASE_SIGNING_KEY` с полным содержимым приватного PEM, включая строки BEGIN и END. В репозитории должна быть включена работа Actions.

Собери первую версию с новым ключом и своим адресом:

```powershell
pwsh ./Release/release.ps1 -Key "C:/Kot-Keys/release-private.pem" -Repository "USERNAME/kot"
```

Первую сборку своего форка нужно установить вручную. Официальная версия не примет обновление с чужим ключом. Дальше используй один и тот же ключ для всех выпусков; workflow сам берёт адрес текущего репозитория.

## Что происходит при обновлении

В настройках есть автоматическое скачивание и установка. Пока kot. работает, он проверяет источник при запуске и раз в сутки. Ручная проверка показывает кнопку «Обновить», без немедленной установки.

Новый ZIP проверяется по подписи и хешам. Потом приложение отключает своё ядро и пинг, заменяет файлы в текущей папке и перезапускается. Если VPN был включён, пробует восстановить подключение. При ошибке записи или запуска интерфейса предусмотрен откат. Профиль и HWID остаются на месте.

Перед стабильным выпуском нужно вручную проверить этот путь на Windows, включая активный VPN и откат. Сейчас полностью проверены пакет и основная логика, но не весь сценарий с настоящими окнами. Установщик ещё без Authenticode-сертификата; подпись ZIP не убирает предупреждение SmartScreen.
