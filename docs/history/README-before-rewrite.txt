НОВОЕ В 0.3.0
- Шрифт Manrope включён в ui/fonts/Manrope.ttf. Кириллица и все веса
  работают без скачивания шрифта из интернета; лицензия SIL OFL приложена.

  запуск ядра. Это реальный трафик, который обрабатывает sing-box, включая
  маршруты напрямую, не скорость тарифного плана и не все адаптеры ПК.
  Счётчики читаются раз в 2 секунды. Первый замер ждёт следующей точки;
  недоступная статистика отмечается явно, остановка показывает ноль.
- «Логи» слева: вкладки «Соединения» и «Журнал». Соединение показывает
  адрес назначения, TCP/UDP, имя процесса (когда Windows определяет его),
  цепочку выхода и принятые/отправленные байты. Клик раскрывает вход,
  правило и время начала. Видны только активные соединения текущего ядра,
  максимум первые 300. Короткие соединения между опросами могут не попасть
  в список. Системная история всех соединений на диск не записывается.
- Поиск, фильтр ошибок/предупреждений, пауза отображения, копирование
  полного журнала. Пауза не останавливает туннель или сбор журнала. В окне
  показаны последние 64 КБ символов, полный экспорт сохраняет лимит 1 МБ
  символов текущего запуска и прежнее скрытие ключей/ссылок/HWID.
  Адреса посещаемых сайтов намеренно видны в «Соединениях», поэтому скриншот
  этой вкладки может раскрывать вашу активность. Имена процессов показываются
  без полного пути и имени пользователя. API-пароль не передаётся в WebView.
- «Настройки -> Обновления»: GitHub Releases (owner/repository) или JSON
  по HTTPS на VPS. Фоновая проверка после запуска и раз в сутки, установка
  по кнопке с проверкой подписи и всех хешей, прогресс и отмена загрузки.
  Источник пока пуст: реальный репозиторий/VPS пользователь ещё не выбрал.
  Подробности публикации и подписи: UPDATE-HOSTING.md и Release/HOSTING.md
  в исходниках. Прежнее обновление из локального ZIP сохранено.

kot. 0.3.1 - Windows 10/11 x64

УСТАНОВКА / ПЕРЕХОД С 0.1.x
Закройте старую версию через меню трея -> Выход. Распакуйте ВЕСЬ новый
архив в постоянную папку и запустите Kot.exe. Можно оставить старую
папку рядом. Профиль находится в %LOCALAPPDATA%\KotVPN, поэтому серверы,
HWID, темы и настройки сохраняются. Старая одиночная подписка автоматически
становится первой в новом списке. Формат 0.2.0 сохраняет и старые поля;
одновременный запуск разных версий не поддерживается.
Если переносите папку вручную и включён автозапуск, выключите/включите его
в новой версии: задача Планировщика должна указывать на новый Kot.exe.
.NET включён. Нужны права администратора для TUN. При отсутствии WebView2
открывается вложенный официальный Install-WebView2.exe; ему нужен интернет.

НОВОЕ В 0.2.1: АККУРАТНАЯ ПАПКА
Библиотеки .NET и самого приложения включены в Kot.exe средствами штатной
single-file сборки .NET. Установка .NET отдельно по-прежнему не нужна.
Снаружи остаются только две DLL: WebView2Loader.dll и core/libcronet.dll.
ui, core, лицензии и установщик WebView2 остаются рядом, распакуйте весь архив.
Kot.exe стал больше, зато сотни DLL и папки локализаций исчезли из поставки.
Single-file допускает распаковку встроенных native-библиотек в системный
кэш %TEMP%/.net, если она необходима runtime.
Обрезка runtime (trimming) и сжатие сборок не включены: этот релиз меняет
упаковку, а не состав зависимостей или работу подключения.
Переход с 0.2.0 выполняйте ручной распаковкой в новую папку: проверяющий
обновления в 0.2.0 требовал отдельный Kot.dll. В 0.2.1 это требование снято,
с сохранением проверки подписи и хешей каждого файла; обычные старые
многофайловые подписанные релизы тоже проходят новую проверку.

  подписку. Выбранный сервер и избранное сохраняются отдельно у каждой.
  Удаление действует только на текущую подписку. Если туннель был включён,

- Звёздочка у сервера: избранное. «Авто» выбирает из избранных серверов;
  если избранного нет, используются все серверы текущей подписки.
  sing-box URLtest измеряет HTTP-доступ через каждый кандидат, выбирает
  доступный быстрый сервер и периодически перепроверяет. Это автоматический
  выбор и смена маршрута для новых соединений, не распределение нагрузки.
  На главном экране «Авто» показывает фактически выбранный сервер,
  полученный через API ядра на loopback с случайным паролем.
- Восстановление после выхода ядра, обрыва сети, изменения адреса адаптера
  и выхода Windows из сна. Паузы неудачных попыток: 2, 5, 10, 20, 30,
  далее 60 секунд. Без сети повтор ждёт появления адаптера. Ручное
  отключение/отмена прекращает восстановление. После успешного подключения
  HTTP-доступ через туннель проверяется каждые 30 секунд; три неудачных
  проверки признают потерю связи. Если восстановление выключено, соединение
  отключается без автоматического повторного подключения.
- Настройки -> Автоматизация: восстановление, обновление всех подписок,
  фоновый пинг и параметры «Авто». Подписки по умолчанию обновляются
  раз в 6 часов; ошибка не стирает рабочие серверы, повтор через 15 минут.
  Фоновый пинг по умолчанию выключен; использует метод, адрес, таймаут,
  попытки и параллельность из обычных настроек пинга. 0 отключает интервал.
  Проверки не стартуют во время импорта/смены настроек и подключения.
- Резервная копия: Настройки -> Дополнительно -> Резервная копия.
  Все подписки и настройки сохраняются в .kotbackup, защищённый AES-256-GCM
  с PBKDF2-SHA256, 300000 итераций, случайными salt/nonce и паролем
  от 8 символов. Переносится между компьютерами. Восстановление заменяет
  профиль, отключает соединение и оставляет зашифрованный предыдущий профиль
  в profile-before-restore.bin. HWID не копируется: он остаётся ID этого ПК.
- Повторный запуск Kot.exe открывает уже работающий экземпляр.
- Настройки -> Дополнительно -> Обновить из ZIP: проверяет подпись RSA-3072,
  SHA-256 всех файлов, версию и пути архива. Не принимает неизвестные,
  повреждённые, неполные и более старые сборки. Новая версия распаковывается
  в отдельную папку, ждёт закрытия старой и запускается. Старая остаётся
  для возврата. При включённом автозапуске задача перенаправляется на новый EXE.
  Для первого перехода с 0.1.x используйте обычную распаковку, как выше.

ПОДКЛЮЧЕНИЕ И ПИНГ
Нажмите +, вставьте HTTPS-подписку, выберите сервер или «Авто», подключитесь.
Импорт: обычные списки URI и Base64; VLESS с TLS/Reality, VMess, Trojan,
Shadowsocks без plugins, Hysteria2 без port hopping. Транспорты TCP,
WebSocket (включая early data), gRPC, HTTP/2, HTTPUpgrade, где применимы.
Готовые Clash YAML, sing-box JSON, XHTTP, SS plugins, VLESS encryption
и закрытые зашифрованные форматы провайдеров пока не поддерживаются.
Ошибочные строки пропускаются с объяснением в «Дополнительно».

«Весь интернет»: TUN, IPv4/IPv6, strict_route, DNS через DoH. Локальная
сеть напрямую. «По правилам»: домены/поддомены из дополнительных настроек
также напрямую. «Подключено» появляется после успешного HTTPS-запроса
через туннель; таймера, имитирующего успех, нет.

«Серверы» -> график: пинг всех, прогресс и «Стоп». Отдельная кнопка пинга
у строки проверяет один сервер. Соседняя кнопка: метод/адрес/таймаут/попытки/
параллельность/сортировка. HTTP использует временное ядро без TUN и свежий
запрос через выбранный сервер без прямого fallback; успех только 2xx,
redirect не считается успехом. TCP проверяет порт, не работоспособность туннель.
Для Hysteria2 нужен HTTP. Результат: медиана успешных попыток.
Временные ядра очищаются при отмене/выходе; остатки конфигов удаляются
при следующем запуске. Измерения могут создавать трафик у провайдера.

HWID
x-hwid, x-device-os, x-ver-os, x-device-model отправляются при импорте
и обновлении подписки, включая фоновые обновления. ID постоянен для kot.
на данном ПК: hash с префиксом приложения от Windows MachineGuid либо
сохранённый случайный ID. Сырые MachineGuid/MAC/имя ПК не передаются.
ID хранится отдельно в device.bin под DPAPI. Он не копирует ID Happ/Incy.
Лимит устройств и требования закрытых панелей определяет провайдер.
Заголовки HWID сохраняются только при перенаправлениях на тот же HTTPS
домен/порт; на другой origin не пересылаются и не восстанавливаются.
Настройка «Передавать HWID» отключает их для последующих запросов.
Документация совместимого формата: https://docs.rw/features/hwid-device-limit/

ДАННЫЕ И ЛОГ
profile.bin зашифрован Windows DPAPI текущего пользователя и не переносится
как обычный JSON. Для переноса используйте .kotbackup. Ссылка не хранится
в localStorage; WebView2 работает только с локальным интерфейсом.
Временный runtime.json содержит параметры при старте, удаляется после
успеха, остановки и при следующем запуске. device.bin хранится отдельно.
«Скопировать полный лог» под ошибкой и в «Дополнительно»: журнал текущего
запуска с этапами, stderr/stdout, вложенными исключениями и стеками.
Лимит 1 МБ символов, потеря начала отмечается явно. Перед копированием
маскируются ссылки, ключи всех сохранённых серверов, HWID и пути пользователя.
Сырые журналы на диск не пишутся. Не удаляйте device.bin для исправления ошибок.

ОСТАВШИЕСЯ ГРАНИЦЫ
Kill switch отсутствует: при остановке туннель возможен обычный прямой интернет.
Онлайн-проверка и загрузка обновлений реализованы, но живой хостинг ещё
не настроен. Для работы нужен опубликованный GitHub Release либо VPS JSON
с подписанным ZIP. Без источника фоновая проверка не выполняется.
Нет Windows-службы, MSI/установщика и Authenticode-подписи Windows.
Для личного использования текущая поставка portable, с UAC и задачей
автозапуска. Не заявляется совместимость со всеми панелями/протоколами.
