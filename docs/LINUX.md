# Ubuntu Linux — предварительная сборка

**Полный перенос пока не завершён.** Статус и проверенные сценарии:
`LINUX_PORT.md`, `LINUX_TEST_REPORT.md`. Не используйте непроверенную защиту
как гарантию отсутствия утечек.

Начиная с `0.8.0~linux0.2`, вкладка **Сервисы** убрана из Linux-версии.
Дополнительные сервисы не запускаются автоматически и не проверяют обновления,
в том числе после импорта Windows-профиля. Их старые настройки и скачанные пакеты
не удаляются. В Windows вкладка сохранена. Перед обновлением полностью выйдите
из предыдущего клиента, чтобы он штатно завершил ранее запущенные сервисы.

## Сборка

Нужны Ubuntu x86_64, .NET SDK **10.0.401**, Go **1.27.3**, Python 3.12+ и dpkg-dev.
Зависимости NuGet закреплены в `Linux/packages.lock.json`, Go — в закреплённом
архиве Xray с SHA-256 и `go.sum`. Не отключайте TLS или проверку Go checksum DB.

```sh
sudo apt install python3 python3-gi gir1.2-gtk-3.0 gir1.2-webkit2-4.1 \
  gir1.2-secret-1 gnome-keyring pkexec polkitd iproute2 nftables \
  systemd-resolved dpkg-dev
python3 Linux/build.py
```

Самостоятельный .NET runtime включён в пакет; Microsoft Windows Runtime и Wine
не нужны. WebKitGTK берётся из репозитория Ubuntu и получает security updates.

## Установка и запуск

```sh
sudo apt install './artifacts/linux/kot_0.8.0~linux0.2_amd64.deb'
kot
```

Запускайте из пользовательского GNOME-сеанса, **не через sudo**. Secret Service
должен быть доступен, связка ключей разблокирована. При проблеме данные не
перезаписываются и не сохраняются открытым текстом. Для переноса с Windows
используйте резервную копию `.kotbackup` с паролем, а не DPAPI `profile.bin`.
Linux создаёт собственный стабильный HWID; провайдер может посчитать его новым
устройством. Windows machine GUID и DPAPI-идентификатор не копируются открытым текстом.

Для TUN/kill switch polkit запросит пароль администратора. Helper запускает
только комплектное ядро от системного пользователя `kot-core`, получает TUN FD
и применяет фиксированные сетевые операции. Сторонние firewall-правила не меняет.
Режим системного прокси применяет пользовательский GNOME HTTP/HTTPS proxy;
это не перенаправляет весь UDP и программы, игнорирующие настройки GNOME.

Закрытие при «Закрывать в трей» сворачивает окно, не прячет его: так приложение
остаётся доступно в GNOME Overview даже без расширения AppIndicator. Выход:
меню индикатора либо выключить настройку и закрыть окно.

## Восстановление сети

Сначала полностью выйдите из kot. Для восстановления **только его** изменений:

```sh
/usr/lib/kot/Kot.Linux --restore-proxy
pkexec /usr/lib/kot/network-helper.py recover
```

Вторая команда явно снимает kill switch. Не делайте этого, если нужна сохранённая
аварийная блокировка. Не выполняйте `nft flush ruleset`, не сбрасывайте UFW,
не перезаписывайте `/etc/resolv.conf`. DNS назначается только собственному
`kot-tun`; удаление интерфейса освобождает его DNS, не меняя профили NetworkManager.

Kill switch сохраняется в ядре при аварии, но **не переживает перезагрузку ОС**
в этой предварительной версии. Ранний старт системы не защищён. Политика
постоянной загрузочной блокировки остаётся работой для следующего этапа.

## Обновление / удаление

Полностью выйдите из клиента. Если после аварии осталась блокировка, сначала
примите явное решение о восстановлении сети. Затем установите новый `.deb`
через apt или выполните `sudo apt remove kot`. Скрипты отказывают в удалении
работающего helper/активной защиты вместо молчаливого открытия трафика.

Профили в `$XDG_DATA_HOME/kot`, журнал прокси в `$XDG_CONFIG_HOME/kot`, кэш в
`$XDG_CACHE_HOME/kot`, ключ Secret Service и UID kot-core сохраняются при удалении.
Linux self-update по Windows Setup запрещён; publisher-signed Linux-канал ещё
не реализован. Локальная сборка `.deb` не притворяется подписанным обновлением.
