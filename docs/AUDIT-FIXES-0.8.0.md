F1 читает только актуальное желание пользователя о защите; сетевые параметры соединения остаются одним снимком. Готовность TUN относится к текущей сессии и сбрасывается при остановке. Настройка и применение фильтров выполняются в UI-контексте, проверки отмены стоят перед применением защиты.

F2 регистрирует операцию до ожидания семафора и открытия файла. У каждой операции свой токен и уникальный ID. Backend проверяет отмену до побочных действий и после асинхронных этапов; UI игнорирует результаты и finally старой операции. Применение импортированных данных вынесено без общего переписывания приложения в ImportApplication.cs, чтобы тестировать настоящие обработчики отдельно от WinForms.

F3 не присваивает квитанцию плохому файлу. При чтении старого кэша совпадающий хеш больше не заменяет проверку вложенных записей. Одна подготовка выполняет не более одной загрузки каждого требуемого файла; отказ не запускает бесконечный цикл скачивания и не удаляет чужие/предыдущие ревизии.

F4 использует хеш сохранённых правил, URL и интервала обновления как базовую ревизию. Ревизия вычисляется из данных, поэтому отдельного нового поля в пользовательском файле нет и неудачная запись не может сама продвинуть ревизию. Timestamp обновления не входит в хеш.

F5 сопоставляет значимые параметры канонически, сохраняет прежний ID при однозначном совпадении и сначала учитывает точные ID дубликатов. Из полного конфига для сравнения исключены только remarks/ps/meta, которые также удаляет XrayConfig.Runtime. DNS, маршрутизация, ключи и транспорт остаются значимыми. Благодаря сохранению прежних ID отдельная конверсия пользовательского файла для миграции не нужна.

Браузер: Playwright 1.63.0, Chromium 153.0.8010.0 из пакета @sparticuz/chromium 153.0.0. Загрузка стандартного браузера Playwright блокировалась сетевой политикой. В flags_ui проверка «только локальные ресурсы» эквивалентно проверяла единственный localhost origin вместо file:. Исходный тест в репозитории не изменён; адаптер находится в validation/local_browser_runner.py внутри архива. На системном Chromium 155 тест демонстрации не доставлял второй click в iframe и падал также на исходном коммите; на Chromium 153 полный тест прошёл. Тайм-ауты и утверждения приложения не ослаблялись. Новый UI-стенд ускоряет только 120-секундный RPC-тайм-аут до 1200 мс, как тестовый стимул сценария F2.

Проверка отрицательного контроля: новые утверждения запущены с исходными проверяемыми операторами 44cde33 в отдельной копии. Все F1–F5 ожидаемо падают по соответствующему поведению, а не из-за ошибки сборки. Для компиляции подключены тестовые помощники; старый local-import перегружен только адаптером сигнатуры с новым cancellation-параметром. Оригинальный старый метод остаётся неизменным. Логи находятся в logs/negative внутри подготовленного архива; validation/setup-negative-controls.py в архиве описывает подготовку стенда. UI старого коммита также падает на отсутствии operationId файлового импорта.

Точные оставшиеся проверки перед stable на настоящей Windows:

1. Измерить фактические WFP-фильтры и исходящий трафик при false→true и true→false в каждой фазе: ожидание assets, native-check, health/DNS, уже установленное соединение. Повторить для системного прокси и TUN, затем для автоматической смены узла после изменения настройки. Проверить ошибку сохранения и отменённое поколение: состояние должно соответствовать последнему успешно сохранённому выбору.
2. Проверить подключение/отключение и отмену, падение Xray, потерю/восстановление сети, переподключение, сон/возобновление. Измерить DNS через TUN, восстановление прежнего системного прокси и сохранение защиты при аварийном выходе. После намеренного снятия защиты/удаления приложения не должны оставаться блокирующие фильтры.
3. В настоящем WebView2 закрыть выбранный файловый импорт во время проверки; довести обычный импорт до реального RPC-тайм-аута; начать новую операцию до позднего ответа старой. Убедиться по сохранённому профилю и процессу Xray, что отменённая операция не останавливает прежнее соединение и не применяет подписку. Отдельно проверить отмену на границе уже начавшегося teardown.
4. Через настоящий мост повторить конфликт маршрутов с фоновым новым block-правилом: backend отказывает, черновик остаётся, явный сброс загружает новую версию. Проверить ошибку сохранения без изменения рабочей ревизии.
5. Обновиться с действительно опубликованной v0.7.3 (GitHub latest проверен: опубликован 17 октября 2026, не prerelease) на этот кандидат. Проверить DPAPI-профиль, активную/неактивную подписки, выбор, избранное, маршруты, режим, системный прокси и откат после неудачного обновления. Проверить переименование узла провайдером и значимое изменение транспорта.
6. Выполнить установку, переустановку и удаление с сохранением/удалением данных по выбранному сценарию, в том числе с активной защитой. Сохранить результаты штатных WindowTests (включая --tunnel-test и --setup-ui-test) и install/release проверок.
7. Повторить govulncheck с доступной актуальной базой уязвимостей.

Готовность stable не подтверждена. Исправления F1–F5 и доступные Linux/browser/native проверки выполнены, но реальные Windows-фильтры/трафик, установщик, upgrade с v0.7.3 и сетевой recovery остаются непроверенными; govulncheck заблокирован средой.
