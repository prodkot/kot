# Изменения в kot.

Для ошибки открой [Issue](https://github.com/prodkot/kot/issues) с версией клиента и Windows, шагами воспроизведения и ожидаемым результатом. Скриншоты и очищенные логи помогают. Ссылки на подписки и данные серверов публиковать не нужно. Уязвимости сообщай [приватно](SECURITY.md).

Начни с [START-HERE.md](START-HERE.md) и обязательной [политики жизненного цикла](Release/LIFECYCLE.md). Dev допускает новые функции, эксперименты и переработки; Beta предназначена для стабилизации и требует прямого разрешения владельца на крупные новые функции. Локальная сборка с меткой Beta без полной Windows-приёмки остаётся локальным кандидатом Beta. Stable выпускается только после приёмки, без известных критических регрессий.

Для изменения кода создай отдельную ветку. Для локальной Dev-сборки выполни проверки затронутого поведения. Открывай pull request, когда передаёшь изменение на ревью. Опиши проблему, итоговое поведение и выполненные проверки. Изменения интерфейса сопровождай скриншотом. Тесты должны проверять поведение, особенно восстановление настроек Windows, отмену операций и ошибки обновлений.

Границы компонентов описаны в [архитектуре](docs/ARCHITECTURE.md), общие стили и контроллеры в [устройстве UI](docs/UI-ARCHITECTURE.md). Выбирай проверки по [матрице](docs/VALIDATION.md). Для работы с агентами используй [AGENTS.md](AGENTS.md); эти правила сохраняют профили, UI/RPC-контракты и безопасность сетевых операций.

Команды сборки и проверок находятся в [docs/BUILD.md](docs/BUILD.md), выпуска версии в [Release/GITHUB.md](Release/GITHUB.md). Версии зависимостей и GitHub Actions должны быть закреплены; при добавлении компонента обнови [THIRD-PARTY.txt](THIRD-PARTY.txt) и тексты в `licenses/`.

Публикация, слияние в main и замена опубликованного установщика требуют явного разрешения владельца. Beta публикуется только как GitHub Pre-release, Stable только из main как обычный Release. Успешный PR или сборка такого разрешения не дают. В отчёте отдельно указывай выполненные успешно, ошибочные, недоступные и невыполненные проверки; не называй Chromium или компиляцию тестами Windows.

В исходники не входят сборки, кэш, профили пользователей и приватный ключ издателя. Нужные runtime-файлы и лицензии формирует сборка; пользовательские файлы при установке не удаляются по расширению.
