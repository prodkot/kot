# kot-ui-system

Начни с действия человека. Например, для смены сервера важно знать, какой сервер выбран, где окажется фокус после обновления списка и в какой момент выбор действительно применён. Затем сопоставь элементы экрана с ролями из каталога kot.

## Откуда брать визуальные решения

Для каждого нового продукта kot наследуй [каталог токенов](assets/tokens.json) и комплектный Manrope по умолчанию. Это базовые цвета обеих тем, типографика, интервалы, скругления, геометрия контролов, движение и состояния. Внутри клиента исходником служит `Windows/ui/styles/tokens.css`. В самостоятельном проекте достаточно этого скилла. До выбора стилей открой [руководство по токенам](references/tokens.md). В нём есть команды экспорта в CSS и WPF, рецепты компонентов, правила исключений и проверка на новом Windows-приложении.

## Как пользоваться

1. Найди ближайший действующий аналог. В kot прочти его разметку, итоговые стили с поздними переопределениями, обработчик события, источник данных и тест. Сверь с `docs/UI-ARCHITECTURE.md`, документом функции и `docs/VALIDATION.md`. В другом проекте привяжи роли kot к ресурсам его платформы. Сверь существующие компоненты с каталогом перед расширением.
2. Назови цель, главное действие и видимые состояния. Укажи, кто подтверждает результат, кто хранит временный ввод, что принадлежит пользователю во время обновления и когда операция заканчивается.
3. Прочти нужные разделы ниже. Выбери семейство компонента, точку возврата, неподвижные ориентиры и способ проверки. Если движение ничего не объясняет, статический переход достаточен.
4. Для движущегося элемента выбери видимый ориентир (край, штрих буквы, центр значка). Заранее определи, как сравнишь его на соседних кадрах при обычном ходе и в момент смены цели.
5. До правки зафиксируй исходное состояние и ожидаемую разницу. После правки воспроизведи обычный путь, прерывание и восстановление через настоящий вход в функцию. В ревью укажи наблюдаемый результат и границы проверки.

## Как отличить принцип от детали

В каждом разделе сначала даны решения, которые можно переносить, затем ориентиры в коде kot. Пути к исходникам отсчитываются от корня репозитория. Основные примеры сверены с 0.8.4 (`839ba31`). Покадровые примеры движения сверены с локальной разработкой 0.8.5 (`73b8840`). При расхождении повтори наблюдение на целевой версии и зафиксируй причину.

В kot сохраняй одобренные роли, поведение и визуальный результат соседних элементов. В новом продукте компоновку, порядок действий и модель ввода определяет задача. Для видеоредактора это предпросмотр и таймлайн, для VPN-клиента это состояние подключения и выбор сервера. Оба используют одни роли цвета, текста и контролов. Отклонение от токена требует причины и проверки. Например, клавиша Back может выполнять роль Escape. Проверка общая: одно нажатие закрывает верхний слой, предыдущая задача и её ввод доступны для продолжения.

**Критерий готовности.** По интерфейсу понятно, что можно сделать и что уже произошло. После повторного ввода, ошибки, смены размера или отключения движения сохраняются верные состояние, геометрия и фокус. Приложи наблюдение, которое отличает такое поведение от правдоподобного, но ошибочного результата.
