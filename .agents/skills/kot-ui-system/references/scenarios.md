# Validation: пять задач для проверки Skill

Возьми задание в кавычках, до просмотра результата выбери разделы Skill, сформулируй решение и одну проверку, которая могла бы его опровергнуть. Ниже приведены разбор и воспроизводимые пробы. Примеры новых возможностей изолированы от приложения.

### 1. Новый компонент

«Добавь индикатор экспорта. Общий размер станет известен после подготовки». Из Design берём соседнее семейство прогресса, из UX различие между отсутствием данных и нулём. В прототипе есть именованный индикатор и текстовый статус. Для неизвестного объёма показывается «Подготовка», для известного обновляются текущее значение и максимум. Движение заполнения не должно оценивать длительность работы.

Проба `component` в [браузерных примерах](../evals/web_examples.py) проходит в обеих темах. Состояния по порядку: неизвестно, 0 из 100, 72 из 120, снова неизвестно. Ожидаемые значения позиции нативного progress: -1, 0, 0.6, -1. Если присвоить неизвестному объёму нулевой процент, проверка различает их на первом шаге.

### 2. Новый диалог

«Дай изменить порог экспорта и вернуться к форме после случайного Escape». Из UX следуют черновик, безопасная начальная кнопка подтверждения и возврат фокуса. Используем существующий менеджер диалогов. При новом открытии загружаем исходное значение, а возврат из подтверждения продолжает текущую сессию.

Проба `form_and_focus` вводит 17 вместо 10 с клавиатуры. Первое Escape переводит фокус на «Продолжить редактирование», второе возвращает к полю со значением 17. Явный сброс закрывает оба слоя, возвращает фокус инициатору, при новом входе поле снова содержит 10. Тест заметит потерю черновика, даже если экран после выхода выглядит правильно.

### 3. Новая анимация

«Добавь новому окну анимированный уход, разреши сразу передумать и открыть его снова». Из Motion берём переход менеджера, текущий видимый кадр, право завершить только действующую сессию и отдельную проверку reduced motion. Это даёт ожидаемый результат и при коротком движении, которое трудно заметить глазами.

Проба `interrupted_motion` перематывает вход к 70 мс, сверяет прозрачность видимого кадра с первым кадром ухода и сразу открывает окно снова. После завершения эффектов ожидаются видимое окно и ноль событий закрытия. Затем при повторном уходе включается reduced motion. Ожидаются одно закрытие, фокус у инициатора и ноль оставшихся эффектов.

### 4. Изменение существующего UI

«Сделай подсказку в узком сайдбаре читабельной, сохрани поведение развёрнутого». Из Design и UX следуют привязка к кнопке, ширина по содержимому, доступность по фокусу и размещение в окне. Для короткого имени допустима узкая подсказка. С длинным именем она может выступать за край панели.

В kot запусти `python Tests/ui_polish.py`, сценарий `sidebar_tooltip`. Он проверяет оба состояния панели, четыре размера окна и имена разной длины, включая арабское. Контрольный опыт на 0.8.4 при viewport 840 × 620: у кнопки шириной 47 CSS px подсказка «Германия · Франкфурт» заняла 148 px. Временный `max-width:44px` в браузере провалил проверку ширины, снятие ограничения восстановило результат. Эти измерения относятся к выбранному шрифту и строке.

### 5. Перенос в другой стек

«Сделай экран экспорта в терминальном приложении. Есть клавиатура, всего 40 колонок и своя тема». Берём подтверждённое состояние задачи, доступную отмену, сообщение об ошибке и возврат фокуса. Здесь палитру и шрифт задаёт пользователь в терминале. Это локальное исключение для терминального порта: сохраняй выбор пользователя, роли и контраст. В терминале с управляемым true color и без пользовательской темы возьми цвета из каталога. Статичной подписи занятости достаточно. Актуальность ответа проверяем по сессии экспорта.

В [терминальном примере](../evals/terminal_port.py) тестовый драйвер Textual нажимает Enter, Escape и снова Enter. Запоздавший успех первой попытки оставляет вторую в ожидании с фокусом на отмене. Ошибка второй попытки возвращает фокус к повтору, третья завершается успешно. Nord и Textual Light проверяют поведение при принудительной теме терминала. Визуальную идентичность нового графического приложения проверяет [автономный Windows-пример](tokens.md#проверка-с-нуля). Он проверяет взаимодействие в тестовом терминале, а проверка с реальным скринридером требует отдельного прогона на целевой системе.

## Повторить пробы

Из корня kot с браузерным окружением из `docs/VALIDATION.md`:

```sh
python .agents/skills/kot-ui-system/evals/web_examples.py
python Tests/ui_polish.py
```

Для автономной пробы скопируй каталог Skill в другое место. В отдельном Python-окружении с Textual (проверено на 8.2.8) запусти из этого каталога:

```sh
python evals/terminal_port.py
```

Тесты и примеры не поставляются в составе клиентского интерфейса.
